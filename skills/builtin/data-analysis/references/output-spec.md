# 交付格式

## 轻量查询

先答数值和单位，随后给来源、期间与计算口径，最后说明影响理解的限制。无须默认生成整套报告或图表。数据不足时直接给可靠的部分结果与不可计算项，不编造数字。

## 完整分析

会话中先给简明结论与交付判断，再提供实际文件路径。报告采用以下结构，可按任务裁剪：

1. **结论摘要**：最有价值的发现及对应数字、期间、单位；发现数量由证据决定，不强凑三条。
2. **数据与口径**：文件路径、工作表、实际检查范围、行粒度、键、字段、期间、过滤规则及假设。区分全量与抽样；摘要不可取得时说明，不伪造。
3. **质量与处理**：缺失/零/重复/异常数量、公式缓存审计、清洗记录及对结论的影响。
4. **指标与证据**：关键统计表和必要图表，每个发现能追溯到指标、分组与计算口径。
5. **解释与行动**：事实、待验证的解释、建议分别标明。建议与证据相连，写出补充数据或验证方法；相关性不写成因果。
6. **核验与限制**：实际执行的独立核验及结果、未执行项目与原因，逐项给出可交付/带限制交付/暂不可用于该结论。

基本产物为 report.md 与必要的 summary.csv；图表仅在帮助理解时生成。较复杂任务可补 quality.json、清洗记录或可复用脚本。不得声称已生成未实际保存的文件；交付引用只采用实际存在的文件路径，不编造下载地址；正文不暴露无关的宿主机绝对路径。

汇总表列名或附带说明应明确期间、单位和分母，未知保留为空并说明。复杂质量记录建议包含 source、scope、grain、keys、missing、zero_counts、duplicates、formula_audit、processing_log、checks、limitations；这些是建议字段，不是假装存在的新平台接口。

不输出任意“质量 95 分”，不把待检项目写成通过。不要把个人明细、敏感标识或整表倾倒进正文；优先脱敏摘要和统计。
