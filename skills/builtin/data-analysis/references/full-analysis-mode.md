# 完整分析模式

适用于多维比较、趋势、异常、图表和报告。流程：明确问题 → 数据检查 → 计算与探索 → 关键结果复核 → 交付。

## 分析流程

1. 按文件流程确定观察粒度、指标、单位、时间范围与时区；根据实际字段形成分析维度清单。
2. 读取 data-quality.md 检查输入，记录缺失率、解析失败、重复风险、日期覆盖、公式值可用性及处理影响。
3. 按 statistics-rules.md 计算。探索产生的新假设标为探索性发现；相关关系不写成因果。异常值仅标记，必要时比较包含/排除标记值后的结果。
4. 需要图表时按 chart-rules.md 选择目的、图形与标注；不要为凑数量制作图表。
5. 按 validation-checklist.md 独立复核关键数字及结论，记录哪些检查执行了、结果如何、哪些因缺数据/能力不能执行。
6. 按 output-spec.md 交付简洁结论、报告、汇总数据和必要图表。可复用分析另外交付分析脚本及执行说明；确认产物文件真实存在。

## 维度覆盖

只选择字段支持、与问题相关的维度：

- 时间：日/周/月、完整周期、季节性或同覆盖范围比较。
- 分组：产品、门店、地域或用户分层；定义互斥/重叠关系和成员资格。
- 分布：均值、中位数、分位数、极端值影响。
- 结构：分组权重是否改变，整体方向是否与分组方向不同。

若缺少用户注册日期，不计算“新老用户”；若缺少流失用户，不声称代表全部用户。无业务依据的负金额可能是退款，不直接判错或删掉。

## 解释与建议

- **事实**：给出数据、口径、证据表/图。
- **可能解释**：指出与事实相符的机制，同时注明未排除的替代解释。
- **建议**：说明建议依据和下一步验证；需要外部业务背景时标“待业务核实”。

不强制把所有解读留空，也不把没有证据的解释写成确定结论。
