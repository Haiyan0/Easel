# 交付物规格(阶段 6 使用)

## 1. 文件清单与命名

写入 Easel 成品目录 `outputs/<选题>/`（阶段 0 确认选题短名，目录名必须具体且可读）：

- `{日期}_{选题}_正文.md` —— 成文正文（如 `2026-08-27_VR观影APP新手教程_正文.md`）
- `{日期}_{选题}_发布配置单.md` —— 发布配置单（同名）
- `{日期}_{选题}_评分卡.md` —— 量化评分卡（同名，格式见 `scoring-rubric.md` 第 4 节）
- `outputs/<选题>/assets/_working-data.md` —— 内部草稿与阶段记录，交付时保留在 `assets/`，不交给运营
- `outputs/<选题>/assets/sample-update/` —— 样本更新的工作副本、索引、归档与快照

全部路径写入前按 `skills/shared/scripts/output_paths.py` 校验；不得写入 skill 源目录或仓库其他位置。

## 2. 正文文件编排

- 开头一行:文章标题(主标题)
- 按阶段 3 确认的板块顺序编排,板块用 `##` 标题;中间主题各层用 `###`
- 文末附「本文更新日期」一行(时效性信号)
- 不包含任何渠道专属排版(emoji/话题标签只在对应渠道发布时由运营按配置单添加)

## 3. 发布配置单字段

```markdown
# {选题} 发布配置单

## 标题备选(分渠道)
- 主标题:{…}
- 小红书:{…}(含情绪词)
- 知乎:{…}(问题式)
- 公众号:{…}(金句式)
- {其他所选渠道}:{…}

## 摘要
{80-120 字摘要,含产品词+痛点词}

## 话题标签
#标签1 #标签2 …(按渠道列出)

## 渠道改写要点
- {渠道1}:{适配改写要点,如短段落/emoji/话题标签}
- {渠道2}:{…}

## 封面图建议
{主题、主视觉元素、文案建议,供设计/运营参考}

## 发布后监测指引
- 发布 7 天后:在豆包/文心一言/Kimi/DeepSeek 用{核心意图词}提问,检查品牌内容是否出现在回答或引用来源
- 记录:可见率(出现次数/提问次数)、引用率(被引用为答案素材次数)
- 数据反哺:未被引用的意图词 → 下次选题补充
```

## 3.5 评分卡(第三份交付物)

- 内容与格式:`references/scoring-rubric.md` 第 4 节模板(总分/档位/七维分项/基准对比/编造红线/短板项/复核记录)。
- 交付顺序:评分达标(≥70 且未触发红线)后,与正文、发布配置单一起写入输出目录。
- 运营用途:分数与短板项供运营判断修改优先级;「超过 X% 被收录样本」数字可直接用于向上汇报(数据依据:47 篇样本基准)。

## 4. 使用说明(交付时口头/文末告知用户)

- **公众号发布**:正文 Markdown 可用 mdnice / 壹伴一键转公众号排版;配图按配置单「封面图建议」另配。
- **第三方推流**:交付「正文 + 发布配置单 + 评分卡」三个文件即可;若第三方要求 Word,将正文粘贴进 Word 另存。
- **运营可自由修改**:正文与配置单均为可编辑 Markdown,运营改后按配置单渠道要点分发。
