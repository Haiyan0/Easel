## 4. 真实平台：用户自行验收

平台按实际使用需求逐个填写，不必为了试用一次测完所有平台。原有浏览器资料目录存在不代表登录仍有效；需要扫码或短信时由用户本人完成。先做账号识别与只读分析，不要为了测试先注销原账号。

| 平台 | 登录/扫码/必要验证成功 | 昵称/头像正确 | 刷新后仍识别账号 | 分析数据或明确失败提示 | 备注 |
|---|---|---|---|---|---|
| 小红书 | | | | | |
| 抖音 | | | | | |
| 微信公众号 | | | | | |
| 视频号 / 其他实际使用平台 | | | | | |

补测：关闭登录弹窗与“停止登录”分别操作；旧弹窗停止回包不应覆盖新平台弹窗。分析失败后应保留并明确标注旧缓存，点击重试能恢复；只打开页面不应反复启动新的分析任务。

实际发布需另记录所选账号、稿件、媒体、画像和发布结果。只有在实例明确配置 `automated`、已确认内容可对外发布时执行；`manual` 下自动发布被拒绝不算缺陷。6A 生命周期与整合收口前，不建议在承载正式账号数据的旧实例上切换策略做首次发布。

- [ ] 确认框中的稿件、素材与画像和实际选择一致；取消后不产生发布。
- [ ] 确认一次，平台只出现一次发布；快速双击或刷新不造成重复。
- [ ] 模拟短暂断网或关闭弹窗后，能找回原发布状态；“结果未知”不能当作失败而直接反复重发。
- [ ] 改选素材/画像后，确认框与最终发布使用新选择，不偷偷恢复旧素材。
- [ ] 必要短信验证可完成；停止在途任务后状态明确。平台已接纳的发布不一定能撤回，停止不能承诺撤回成功。
- [ ] 在平台后台核对实际稿件与状态，不能仅以 Easel 显示成功作为发布通过证据。
