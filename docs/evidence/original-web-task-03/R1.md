## T3-R1-01：当前身份 401 先结束所拥有身份

修复：

- `useWorkspace` 的当前身份 401 处理统一放在 epoch/selection/seq/owns guard **之前**：
  - 提交 `submit` catch：先看 `identityInvalidated`，再检查 epoch；
  - 初始历史/active-run catch：先 `handleAuthError`，再检查取消/选择/消息代次；
  - `finishRun` 终态快照 catch：先认证错误，再检查 allowed；
  - `questionStatus` 旁路 catch：新增 401 处理；
  - `loadSessionsPage` catch：先认证错误，再检查分页代次。
- 迟到 A 401 仍由 `identityInvalidated` 判定；旧 epoch 401 不调用 `onExpired`，不会踢 B
  或同账号新 epoch。
- `answer` 的 401 也走认证边界，不再作为普通回答失败留在页面。

真实浏览器反例（最终 fixture，基线构建红、修复后绿）：

```text

r1_question_status_401 : 题卡状态查询 401 → 登录页可见、sidebar=0、无残留题卡/发送中
r1_initial_history_401 : 登录后 runs 401 → 登录页“登录已失效”、sidebar=0
```

修复前基线 `8f1c112` 构建：前三条因“等待登录已失效”超时失败；`r1_late_401_keeps_b` 通过
（保留迟到旧 401 回归）。修复后三条均通过。

## T3-R1-02：临时回答失败保留题卡并可原地重试

修复：

- `useWorkspace.answer` 改为返回 `{ok, error?}`：
  - 503/断网/403：保留当前 `question` 与 QuestionCards 的本地选择，返回 `ok:false` 及明确错误；
  - 409：保留原“已过期/已回答”收敛，清除题卡并返回错误；
  - 401：按 T3-R1-01 回登录；
  - 成功：才清除题卡并返回 `ok:true`。
- `WorkspaceApp.answer` 不再无条件包装 `{ok:true}`，直接透传 hook 结果。
- QuestionCards 原有行为只在 `ok:true` 时 `onAnswered`；失败时保留卡片、显示错误、选中项不清空。

真实浏览器反例：

```text

                     POST /api/chat 次数不变（只重发答案，不重发 prompt）
r1_answer_403      : 回答 403 → 题卡仍在、未回登录页；再次提交成功
r1_answer_409      : 回答 409 → 显示“已过期/已回答”，按明确证据移除题卡，不回登录页
```

修复前基线：503/403 场景题卡被移除；409 已按原语义通过。修复后全部通过。

## T3-R1-03：统一单调推进已消费事件游标

修复：

- `connectRun` 新增 `commitFrame`：state/token/thinking/activity/question/error 在 `owns()`
  有效时统一执行：
  - `cursor = max(cursor, frame.id)`；
  - `writeRecovery` 持久化单调游标；
  - 同步更新 `runRef` 与 React 状态（含内容/思考/活动/题卡/游标）；
  - 旧连接迟到回调被 `owns()` 挡住，不回写新连接。
- 同页重连使用 `runRef.current.cursor`，从最后消费位置继续；刷新/重新挂载仍从 0 回放，
  重建未完成内容，不跳过历史帧。

真实浏览器反例：

```text
                    重连请求 after=3；题卡只保留当前一张；POST /api/chat 不增加
```

修复前基线：重连分别从 after=1/after=2 重放，导致 thinking/activity 重复、题卡从旧游标重放；
修复后 after=3，内容唯一，POST 计数不变。
