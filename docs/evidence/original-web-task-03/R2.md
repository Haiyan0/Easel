## 问题

原 `onQuestion` 先 `commitFrame` 推进并持久化游标，再异步查询
`questionStatus`；题卡 payload 只在状态回调里写入。若状态查询未返回时流断开，
用户立即重连，新流从问题事件之后继续，旧状态请求又因归属变化被忽略，页面就
只剩“后台 awaiting_permission”而没有题卡。

## 修复

- `onQuestion` 消费问题事件时，在同一个 `commitFrame` 中同步把题卡视图和
  `questionPending=true` 写入 `runRef` 与 React 状态，再发起状态查询；游标与
  待确认 payload 不再分两步落地。
- 新增 `verifyQuestion`：新连接核对状态时，`pending` 才解除“确认中”；
  `resolved`/`expired`/`not_found` 等明确非 pending 才清除题卡并记入
  `answered`；缺失/未知状态保持待确认，不把未知当成已授权。
- 重连时若继承的 `questionPending` 为 true，立即用**新连接**的 `owns` 继续
  核对；旧连接的迟到 pending/answered 仍被 `connectionSeq`/`owns` 拦住。
- 状态未知期间题卡可见但显示“正在确认问题状态…”，提交按钮禁用；状态失败
  （503/断网）保留题卡，重连后可再次核对。401 仍先走认证边界。
- `answer` 成功和明确 409 同时清除 `questionPending`；local 模式的题卡行为
  不变。刷新/重挂仍从 0 回放，不改变思考/正文重建语义。
