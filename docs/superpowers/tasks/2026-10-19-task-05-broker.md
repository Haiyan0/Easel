## 稳定契约

```python
BrokerService(store: Store, config: ConfigService, clock=time.time)
issue(actor, run_id: str, channel: str) -> str
authorize(token: str, workspace_id: str, run_id: str, channel: str) -> EffectiveRoute
revoke_run(run_id: str, workspace_id: str) -> None

ProviderAdapter.accepts(method: str, relative_path: str) -> bool
ProviderAdapter.prepare(route: EffectiveRoute, method: str,
                        relative_path: str, headers: dict) -> UpstreamRequest
# UpstreamRequest(method, url, headers)，body 独立流传递
```

仅服务器内部服务签发 token，不新增普通浏览器任选 workspace/run/channel 的签发接口。token 使用独立高熵 opaque 值，数据库存摘要，默认有效 1800 秒，绑定 workspace/run/channel/配置版本；错误、repr、日志和响应不得暴露管理员 Key。

## 执行步骤与验收

- [ ] **1. 先红。** 按 plan 写 token 不能改 workspace/channel 的测试，运行 test_broker.py。继续补下列关键失败测试后最小实现；真实 HTTP 鉴权测试不能以 mock authorize 替代。

- [ ] **2. 令牌授权与预算。** 签发和使用都回数据库验证用户、workspace、Run 归属和活跃状态；终态 Run、禁用用户、过期/撤销 token、换 run/channel/workspace 均拒绝。通过跨连接持久化保证重启后撤销仍有效；参数和时间由可注入 clock 验证。复用已有 Run 接纳限制，不重复创建 Run；broker 自身并发检查与释放也必须原子，覆盖每 workspace 2、全局 8，超额 429，异常/取消/断开均释放。

- [ ] **3. 固定真实配置快照。** token 的配置版本不能只是日志字段；管理员或个人配置更新、删除后，已有 token 不得静默切到新地址/新 Key。为当前完整路由及凭证引用保存足够的不可变服务端快照，仍加密存储，供 adapter 按绑定引用解密。必要时追加迁移，不改旧迁移。

  Task 4 的个人覆盖行会覆盖更新，清除后 revision 从 1 重新开始，因此不能只用当前 workspace/channel/version 字符串查询“最新行”当快照。测试签发 → 改个人路由/清除后重建 → 旧 token 的路由/凭证仍固定；新 token 使用新配置。管理员更新同样验证。不得借此将明文 Key 复制进 Run、token 表或 worker。

- [ ] **4. 首批 adapter。** DeepSeek ACP 主模型、image/openai、speech OpenAI-compatible TTS/ASR，逐项列出精确 method+相对 path、协议和模型约束，不用 /v1 前缀泛放行。包含必要模型列表。仅 adapter 的服务器内部代码解密 credential_ref 后构造上游认证，调用者拿不到明文凭证。

  主聊天路由由管理员配置，不能把 chat 加入 member 的个人覆盖允许集。当前 ConfigService 只处理四种能力，需为受管主模型增加最小管理员内部配置/解析支持并记录契约，不能从宿主 .env 或客户端参数回填管理员 Key。保留 speech→voice 映射及唯一 registry，支持矩阵反映实际 adapter，不只检查 metadata 非空。

  验证 provider/protocol/method/path/model 的组合；忽略或拒绝客户端自带目标、Authorization、Host、转发头、凭证引用、URL 绝对路径及路径逃逸。JSON、multipart 的实际模型字段必须与 token 快照约束一致，不能只验证元数据而透传另一个 model。非敏感 options 维持 Task 4 白名单；不借模型请求改变上游路由。

- [ ] **5. 实际 HTTP 边界与流。** 注册精确 broker 路由并实际校验 opaque token；若作为独立内部应用或 control 中独立鉴权分支，不得通过 public /api 前缀绕过原有 Cookie/CSRF 边界。浏览器设置、自检接口仍按其自身身份规则；未接线功能保持明确不可用。

  使用 HTTPX 流式传递 JSON、multipart、二进制与 SSE；保留合法 Content-Type/boundary、状态与必要响应头，剥离 hop-by-hop 及 Connection 指定头、客户端上游认证/身份头。最终 transport 请求不受 client 默认 headers/cookies/auth 再注入影响。上游响应不得透传 Set-Cookie 或泄露凭证；finally 关闭上游，取消/中途错误/SSE 断开均释放流及并发额度。不要缓冲完整 SSE 后伪装流式。

- [ ] **6. 受限出口。** 生产所有请求经独立受控出口代理，缺少代理/策略时明确失败，绝不 silent direct fallback；测试 fake transport 必须显式注入。HTTPS、公网目的地与管理员批准范围在保存/自检/列模型/实际请求采用一致策略；成员不能扩大例外。

  保存时 URL 检查只是前置，连接阶段由出口验证解析后的实际目的 IP，并防止验证后重解析切私网；覆盖 IPv4/IPv6、回环、私网、链路本地、元数据、control/worker/provisioner。默认不跟随重定向，不向跳转目标发送 Key。代理配置要有可运行的部署/测试契约，不能只添加一个未经策略验证的 proxy URL 就宣称完成出口隔离。
